# C++ COM-сервер системы бронирования номеров в гостинице

## 1. Назначение проекта

Серверная часть представляет собой COM-компонент, реализованный на языке C++ с использованием ATL (Active Template Library).

Компонент содержит основную бизнес-логику системы бронирования номеров в гостинице. Он отвечает за хранение данных о номерах и бронированиях, проверку доступности, управление состояниями, расчёт стоимости проживания и формирование статистики.

Сервер предназначен для вызова из клиентских приложений через технологию COM. В рамках проекта клиентская часть реализована на Python с использованием библиотеки `pywin32`, а также на С++.

## 2. Архитектура сервера

Сервер собирается в динамическую библиотеку DLL, которая регистрируется в Windows как COM-сервер.

Основные элементы серверной части:

- **ATL COM-класс** — реализует объект гостиничной системы.
- **COM-интерфейс `IHotelService`** — определяет методы, доступные клиенту.
- **IDL-описание** — задаёт контракт интерфейса, типы параметров и идентификаторы COM.
- **Внутренние структуры данных** — хранят сведения о номерах и бронированиях.
- **Бизнес-логика** — выполняет проверки и операции над данными.

Идентификаторы компонента:

| Элемент | Идентификатор |
|---|---|
| CLSID сервера | `{4f72097e-cf14-45d3-9232-ca002e541fff}` |
| IID интерфейса `IHotelService` | `{5aa88d9e-fae9-407e-a7fa-7a3396394736}` |
| LIBID библиотеки типов | `{f26aa6f4-9f00-4295-85fa-99ee768434bb}` |

## 3. Основные функции сервера

### 3.1. Управление номерами

Сервер предоставляет методы для получения и изменения информации о гостиничных номерах:

- `CheckRoom` — проверка доступности номера;
- `GetRoomInfo` — получение информации о номере;
- `GetRoomsByType` — получение номеров выбранного типа;
- `FindAvailableRooms` — поиск свободных номеров на указанный период;
- `SetRoomStatus` — изменение статуса номера;
- `AddRoom` — добавление номера;
- `UpdateRoom` — изменение данных номера;
- `RemoveRoom` — удаление номера.

Для номера могут использоваться статусы `Available`, `Occupied`, `Cleaning`, `Maintenance` и `OutOfService`.

### 3.2. Управление бронированиями

Методы бронирования обеспечивают создание и сопровождение записей о проживании:

- `BookRoom` — базовая операция бронирования номера;
- `CancelBooking` — отмена подтверждённого бронирования по идентификатору номера;
- `CreateBooking` — создание бронирования с датами заезда и выезда;
- `GetBookingInfo` — получение сведений о бронировании;
- `UpdateBooking` — изменение дат проживания;
- `CheckIn` — регистрация заезда гостя;
- `CheckOut` — регистрация выезда гостя.

В системе используются состояния бронирования, включая `Confirmed`, `CheckedIn`, `CheckedOut` и `Cancelled`.

Методы `BookRoom` и `CancelBooking` сохраняются как базовые методы MVP. При этом `CancelBooking` принимает идентификатор номера (`roomId`), а не идентификатор бронирования (`bookingId`).

### 3.3. Расчёт стоимости

Сервер предоставляет методы:
- `CalculateBookingPrice` — расчёт стоимости проживания;
- `ApplyDiscount` — применение скидки к бронированию.
Стоимость определяется серверной логикой на основании данных бронирования и стоимости номера.

### 3.4. Статистика

Метод `GetHotelStatistics` возвращает сводную информацию о гостинице. Результат может содержать агрегированные данные о номерах и бронированиях.

## 4. Внутренние данные

Для хранения информации используются структуры данных C++.

### Номер

Запись номера включает данные, необходимые для идентификации номера, определения его типа, вместимости, стоимости и текущего состояния.

В начальном наборе данных предусмотрены номера с идентификаторами от 101 до 107:

- номера 101–103 относятся к типу `Standard`, вместимость — 2 человека, стоимость — 3000;
- номера 104–107 относятся к типу `Deluxe`, вместимость — 4 человека, стоимость — 5000.

### Бронирование

Запись бронирования содержит:

- идентификатор бронирования;
- идентификатор номера;
- имя гостя;
- дату заезда;
- дату выезда;
- статус бронирования;
- размер скидки.

Данные обрабатываются сервером, а клиент получает результаты через методы COM-интерфейса.

## 5. Обмен данными с Python-клиентом

Для взаимодействия используется COM-интерфейс `IHotelService`.

Python-клиент создаёт экземпляр объекта по CLSID и вызывает его методы через `IDispatch`. Параметры методов передаются в соответствии с контрактом интерфейса.

Для передачи сложных структур сервер возвращает JSON-строки. Например, метод `GetRoomInfo` возвращает данные об одном номере, а `GetHotelStatistics` — сводную статистику.

На стороне Python эти строки преобразуются в словари и списки с помощью стандартного модуля `json`.

Таким образом, серверная логика не зависит от способа отображения информации на клиенте.

## 6. Сборка проекта

Для сборки требуется Windows и установленная среда Microsoft Visual Studio с компонентами разработки на C++.

1. Откройте решение проекта в Visual Studio.
2. Выберите конфигурацию `Debug` и платформу `x64`.
3. Выполните команду **Build Solution**.
4. Убедитесь, что сборка завершилась без ошибок.
5. Найдите созданную DLL в каталоге сборки.

Пример пути к собранной библиотеке:

```text
x64\Debug\HotelServer.dll
```

Фактический путь зависит от расположения проекта и настроек сборки.

## 7. Регистрация COM-сервера

Чтобы клиент мог создать COM-объект по CLSID, DLL необходимо зарегистрировать в Windows.

Для 64-разрядной сборки используйте командную строку с правами администратора:

```powershell
C:\Windows\System32\regsvr32.exe "ПОЛНЫЙ_ПУТЬ_К\HotelServer.dll"
```

Замените `ПОЛНЫЙ_ПУТЬ_К` на фактический путь к собранной библиотеке.

При успешной регистрации Windows сообщит, что регистрация DLL прошла успешно.

Если DLL была пересобрана и заменена, регистрацию следует повторить для актуальной версии файла. Разрядность клиента и COM-сервера должна быть совместимой.

## 8. Запуск и проверка

COM-сервер не запускается как отдельная консольная программа. Клиентское приложение создаёт экземпляр COM-объекта, после чего вызывает необходимые методы.

Для проверки работы всей системы:

1. Соберите C++-проект.
2. Зарегистрируйте DLL.
3. Установите зависимости Python-клиента.
4. Запустите `demo.py` из каталога `HotelClient`.
5. Выполните несколько операций с номерами и бронированиями.
6. Запустите автоматические тесты Python-клиента.

## 9. Роль серверной части в компонентной архитектуре

Сервер является самостоятельным программным компонентом, предоставляющим функциональность через формально определённый COM-интерфейс.

Клиент взаимодействует с ним через публичный контракт, не обращаясь напрямую к внутренним структурам данных и реализации бизнес-логики.

Такое разделение позволяет независимо разрабатывать и тестировать клиентскую и серверную части, а также повторно использовать сервер из других COM-совместимых приложений.

В рамках проекта сервер реализует бизнес-логику гостиничной системы, а Python-клиент обеспечивает вызов доступных операций и демонстрацию их работы.
